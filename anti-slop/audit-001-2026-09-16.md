# Article management audit — 2026-09-16

Scope: current Laravel + Livewire article workflow and the public shell it relies on. This is an audit only; no product behaviour was changed.

## Requirement coverage

| Requirement | Status | Evidence |
|---|---|---|
| Dashboard index, create, and edit routes behind authentication | Pass | `routes/web.php` registers all three under `auth` and `/dashboard`. |
| Article fields and status storage | Pass, extended | `Article` includes the requested fields plus author, category, tags, cover image, SEO, and `archived`. |
| Livewire editor, validation, Markdown preview, draft/publish time | Pass | `ArticleForm` validates data and renders an in-page Markdown preview. |
| Safe Markdown rendering | Pass | `Markdown` strips raw HTML and unsafe links through CommonMark. |
| Only published articles are public; drafts return 404 | Pass | `Article::published()` and `BlogController::show()` require a past `published_at`. |
| Authorization for dashboard changes | Pass | `ArticlePolicy` allows administrators and limits editors to their own articles. |
| Publish/unpublish actions from the article list | Gap | Actions exist, but `ArticleIndex` exposes archive and delete only. |
| Published date in the article list | Gap | The table shows `updated_at`, not `published_at`. |
| Live slug generation while typing | Partial | A slug is generated safely during save when empty, but the URL field is not updated from the title in the editor. |
| Direct public `GET /articles/{slug}` page | Intentional deviation | Legacy URLs redirect to the canonical localized path (`/id/articles/{slug}` or `/en/articles/{slug}`) for SEO. |
| Automated coverage of all list actions | Gap | Existing tests cover auth, draft visibility, public visibility, scheduling, custom slug, and tags; they do not exercise list publish/unpublish/delete or policy boundaries. |

## Anti-slop findings

1. **HIGH — R-26 / R-36:** The footer subscription form has `onsubmit="return false"`; it presents a working email subscription while deliberately doing nothing. Implement a real subscription workflow with feedback, or remove the form until one exists.
2. **HIGH — R-03:** The public header search and theme controls are `36×36px` (`h-9 w-9`), below the 44px mobile tap-target minimum. The site has had mobile-layout regressions, so this requires device-width verification after correction.
3. **HIGH — R-26:** The dashboard article list does not expose its existing publish/unpublish operations, even though publishing is a core content-management action specified for this screen.
4. **MEDIUM — R-09 / R-36:** The footer's pulsing “All systems operational” indicator asserts a live system state without a status data source. It should be backed by monitoring, replaced with a non-live label, or removed.
5. **MEDIUM — R-31:** The current design system has no written design rationale or declared ENERGY/RHYTHM/MOTION dials. The visual language is consistent, but major decisions such as blue accent usage, monospace metadata, and card surfaces are undocumented.
6. **LOW — R-08:** Directional-arrow treatments appear repeatedly in public article calls to action. Keep them only where the icon helps signal an external or forward navigation action.
